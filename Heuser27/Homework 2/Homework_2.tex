\section*{Recap: Where We Left Off}
In Session 3 we separated \emph{events} from \emph{states}, built a sprite, gave it
velocity, and learned that MakeCode Arcade's four directions and two buttons open up
32 simultaneous input combinations -- more than enough to build something meaningful
with limited inputs. We closed the session by combining sprite effects, the
\texttt{say} bubble, and a boolean flag to make a sprite announce itself only the
\emph{first} time a condition was met.

In Session 4 we talked about something less technical: that skill without wisdom,
perspective, or a story to tell doesn't go very far. We looked at Visual Novels,
RenPy, and itch.io's game jams, and played a short choice-driven game together as a
class to see how a simple, linear, non-looping program can still branch and feel
alive depending on what came before.

This homework asks you to put both halves together: the branching-logic tools from
Session 3, in service of the human, narrative thinking from Session 4.

Using \textbf{Block Code only} (no JavaScript) in MakeCode Arcade, build a short,

\subsection{Theme}
Your game's theme, tone, and palette should draw from:
\begin{itemize}
\item Depression, personal life difficulties, and what it feels like to struggle quietly
\item Suicide prevention and the month of September, where the theme is discussed openly
\item Helping others, companionship, and not facing hard things alone
\item A visual identity built around \textbf{purple} and \textbf{turquoise} -- the two
colours associated with Suicide Prevention Awareness
\end{itemize}

\subsection{Structural Requirements}
Plan this on paper as a branching flowchart \emph{before} you open the editor. Your
finished project must contain exactly:
\begin{itemize}
\item \textbf{40 dialogue lines} at minimum, delivered through \texttt{say} bubbles or
an equivalent dialogue mechanic, spread across the story.
\item \textbf{20 unique questions} (decision points where the player is asked
something and chooses between responses). The \textbf{final 3 questions} should
ideally not be asked in a vacuum -- have them respond to, reference, or build on
choices the player made earlier, using stored boolean or variable state, the same way
we tracked "has this happened before?" with the teleport flag in Session 3.
\item \textbf{Exactly 2 endings.} Both endings must be \textbf{Good Endings}. This
assignment does not allow a bad, sad, or ambiguous ending -- every path through the
story must ultimately resolve with the character finding support, connection, or a
way forward.
\end{itemize}

\subsection{Concepts You Should Draw On}
\begin{itemize}
\item Events vs.\ states, and why button presses in Arcade are events
\item Sprite initialisation, drawing, and (if relevant to your scenes) \texttt{vx}/\texttt{vy}
\item Boolean flags and \texttt{if} statements with equality checks, to branch dialogue
based on earlier answers
\item Built-in sprite effects, the \texttt{say} command, and change-position blocks
\end{itemize}

\subsection{Writing About a Sensitive Topic Responsibly}
Because of the theme, please follow these guidelines while writing your story:
\begin{itemize}
\item Do not depict specific methods or explicit acts of self-harm, and avoid graphic
or triggering imagery.
\item Keep the narrative centred on listening, empathy, and hope rather than on
crisis detail.
\item End the game with a short screen naming one real, currently active crisis
helpline for your country or region. Look one up -- do not guess or invent a number.
\end{itemize}

\section{Constraints \& Expectations}
\begin{itemize}
\item Block Code only. No JavaScript view for the graded logic.
\item Submit a working, shareable project -- not a written script, storyboard, or
description of what the game would do.
\item You must design your own decomposition: which variables track which choices,
how scenes are organised, and how the last three questions call back to earlier ones.
\item The game must be playable start to finish without errors and must always reach
one of the two Good Endings.
\end{itemize}
